生成代码并加载配置

本页继续使用 MiniTemplate，不切换到综合配置工程。两个控制台示例都读取道具 1001，并检查名称和数量。

C# 与 System.Text.Json​

需要 Python 3.9+、.NET 8 SDK 和兼容的 Luban。在 luban_examples 根目录执行：

python scripts/run.py dotnet

命令使用 cs-dotnet-json + json 生成到临时目录，编译 Projects/QuickStart_DotNet_json，加载 JSON 并断言 id=1001、name=道具1、count=10。最后输出 PASS dotnet: 1001: 道具1 (10)。

加载的核心代码：

var tables = new cfg.Tables(file =>
{
    using var document = JsonDocument.Parse(
        File.ReadAllBytes(Path.Combine(dataDirectory, file + ".json")));
    return document.RootElement.Clone();
});
var item = tables.Tbitem.Get(1001);
Console.WriteLine($"{item.Id}: {item.Name} ({item.Count})");

需要 System.Text.Json、System.IO 命名空间。Clone() 让返回值不依赖已释放的 JsonDocument。dataDirectory 是绝对数据目录，由程序参数传入。

JavaScript 与 Node.js​

需要 Node.js 18+、Python 3.9+ 和运行 Luban 的 .NET runtime：

python scripts/run.py node

使用 javascript-json + json，无需 npm 包。生成器输出 ES module，执行器在隔离目录声明 type: module，从 Projects/QuickStart_Node_json/app.mjs 加载并检查相同道具。预期 PASS node: 1001: 道具1 (10)。

两条命令支持 --luban /absolute/path/Luban.dll。--output NEW_DIRECTORY 可以保留代码、数据和构建结果，但拒绝覆盖已有目录。

接入 Unity 或自己的项目​

Unity 可采用 cs-simple-json + json 或 cs-bin + bin，安装 com.code-philosophy.luban runtime 包，并实现符合该生成目标的 loader。不同目标的 loader 参数类型不同，切换格式需要重新生成代码。

默认 Tables 加载和引用解析偏同步；Android StreamingAssets 等不能直接当普通文件路径读取，应先使用平台的资源 API 取得数据。需要异步时在外层封装或定制模板。

示例索引：按语言和引擎选择。接入步骤：集成已有游戏项目。表访问 API 由 mode/index 和生成目标决定，不应假定所有表都有相同 Get 方法。

源项目：C#、Node。
